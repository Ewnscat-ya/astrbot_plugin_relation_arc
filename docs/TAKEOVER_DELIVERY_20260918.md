## 聊天反馈调查

现有转述仍不能确认“你的插件”的具体身份、当时两插件是否同时启用、实际版本/配置、准确 DeepSeek 模型、思考设置或上下文重置情况。关于“思考变少”的后来解释也只是反馈者更正，尚无请求/响应实录证明根因。

已核查的参考是 Favour Ultra `2f2ec141d05052b8f641f29ca04bde8fc97e4d62`（v4.4.5），不是对反馈现场版本的认定。参考文件哈希记录在兼容证据中。工具只提取这份文件的受限提示模板和原始好感度正则，不导入或执行该上游插件；代入合成上下限/账户/关系后，分别与旧/新关系弧线真实 hook 组合。完整本地请求保留在采集目录；仓库保存来源哈希、请求哈希及逐场景结论，可用同一上游源文件重建。

确认的代码边界：

- 原始人设在两种合成人设、单独提示及前后组合中保留。关系弧线首行块与 Favour 末行标签可以同时存在；单凭首行/末行要求不能断定协议冲突。
- 关系弧线清理只针对自己的控制块；合成有效输出中不会吞掉好感度标签。两种清理顺序均验证，不能据此保证未知插件的全部清理逻辑。
- 所读参考源的响应 hook 优先级为 10，关系弧线为默认值；已安装宿主按数值降序排列。实际实例的插件清单、启用状态和完整调度仍未知。
- 提示文本中的 XML `priority="override"` 没有作为独立模型权重参数传给 provider 的代码证据。没有通过缩短/删减人设或再次搬动提示顺序来猜测修复模型漂移。

因此没有证据把现场“标签完全识别不到”归因于本轮已修的归属缺陷，也没有证据宣布现场人设异常已解决。真正的模型行为对照需要 [MODEL_AB.md](MODEL_AB.md) 中列出的最少版本/组合/模型信息与获授权的隔离环境。双评分插件共存不作为新增产品承诺。
