# 存储性能基线（MIS-97）

本文件记录 MIS-97 的实测性能基线与方案裁决。所有数字来自本开发机单次运行（固定种子 `20260912`，脚本 `tools/benchmark_store.py` 可复现），未做未测声明。

## 硬件与环境声明

- 开发机 x64（Windows 10.0.26200），Python 3.12.10，SQLite 3.49.1，本地临时目录存储（无网络盘）。
- 数据集：固定种子合成——账户随机初值，事件随机分布到账户、`created_at` 随机落在 0–3 小时窗口。
- 原则：数字是本机成绩；其他硬件以脚本复现为准，不直接引用本表。

## 方案裁决：专用 worker vs aiosqlite → **维持同步单写者 + 合并窗口 + 索引**

| 候选 | 结论 | 依据（实测） |
| -- | -- | -- |
| aiosqlite（每连接工作线程） | 不采用 | 需要把全部 store 调用点重写为 async，事务串行化要额外设计；而阻塞根因是重复扫描与缺索引，消除后**单轮结算整事务 p95=4.26ms**（500 条窗口事件最坏例），远低于 50ms 阈值——异步化收益不抵风险与改动面。 |
| 专用 worker 线程 + 队列 | 不采用 | 同上；且"每条 SQL 单独丢线程"是执行合同明令禁止的破坏事务模式，整事务搬线程等于自建 aiosqlite。 |
| 同步单写者（现状）+ 合并窗口 + 索引 | **采用** | 单事务内合并窗口读取消除了每维重复扫描；两个索引消除全表扫。事务串行化=既有 `lock`+`BEGIN IMMEDIATE`，连接生命周期=按调用打开关闭，取消=任务取消不中断进行中事务（backup/decay 任务受管 cancel/await）。 |

裁决触发条件（记录以备将来重开）：若真实宿主下出现 p95>50ms 的证据（事件量级或并发模式超出本基线），再评估 worker 方案。

## 实测数据

### 窗口扫描（每轮结算的窗口读取+聚合；40 轮，固定种子）

| 数据集 | 路径 | p50 | p95 | max |
| -- | -- | -- | -- | -- |
| 1k 账户 / 10万事件 | 改前：逐维扫描（12 次全窗口扫 + 逐行重复 JSON 解析），**无索引** | 82.38ms | 88.18ms | 98.74ms |
| 1k 账户 / 10万事件 | 改后：合并窗口 + 索引 | 0.64ms | 0.84ms | 0.99ms |
| 1k 账户 / 10万事件 | 改后：逐维扫描（仅加索引，隔离索引贡献） | 1.39ms | 1.65ms | 2.09ms |
| 10k 账户 / 100万事件 | 改后：合并窗口 + 索引 | 0.82ms | 1.22ms | 1.41ms |

- 索引贡献约 **53×**（p95 88.18→1.65ms）；合并窗口再省约一半（每行 JSON 只解析一次）。
- 查询计划：改前 `SCAN events`（全表扫）→ 改后 `SEARCH events USING INDEX idx_events_window`。
- 100 万事件下 p95 仍 1.22ms——索引使窗口查询不随总事件量线性退化。

### 整轮结算的事件循环阻塞（最坏例：窗口内 500 条该账户 llm 事件，60 轮）

- p50=3.63ms / p95=4.26ms / max=5.55ms（含事务、绑定校验、审计写入）。
- **阈值判定**：建议阈值"事件循环 p95 <50ms"达成，余量 >10×；"10 万事件查询 p95 <200ms"达成（0.84ms，余量 >200×）。阈值按原建议固定，无需调整证据。

## 等价性证明

- 基准脚本内置 `equivalence_check`：随机样本上新旧窗口聚合输出逐值一致（`equivalence_old_equals_new: true`）。
- 测试：`WindowMergeEquivalenceTests` —— 与旧 `repeat_count`/`positive_window_total` 逐维结果逐维比对一致；evidence 拆分、签名匹配、负值分支均有断言。
- 全量 164 用例（含 A06 类原子/幂等/排他/故障注入）双版本通过；行为样例 diff 为空。

## 语义说明（发布说明项）

- 窗口读取合并为一次查询，但**两个窗口语义保持独立**：重复判定窗口 `repeat_window_minutes`（默认 180 分钟）与反刷窗口 `rolling_window_hours`（默认 24 小时）各自过滤时间，不因合并而互相污染。
- 两个新索引随 schema 迁移自动创建（无版本号提升——`CREATE INDEX IF NOT EXISTS` 幂等，旧库升级透明）。
